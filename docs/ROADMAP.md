# Aura roadmap

Aura is an iOS cycling app: plan a route to somewhere, get turn-by-turn voice
navigation, or just start a free ride and record the track. This file records what
is built and what comes next. Dates are when work landed, newest first.

## Shipped

### Foundation and architecture

The code is split into three layers so the routing and navigation engines can be
swapped without touching the UI:

- `AuraCore` is pure Swift with no UIKit, SwiftUI, or Mapbox. It holds the models
  (`Ride`, `Route`, `Place`, `RideStats`), the stats and ranking logic, and the
  protocols that define the seams (`RoutingProvider`, `ElevationProvider`,
  `GuidanceSession`).
- `AuraKit` depends only on `AuraCore`. It has the observable view models and stores
  (`RideRecorder`, `RideStore`, `SettingsStore`), formatting, and the pure plotting
  helpers behind the thumbnails and sparklines. Location streaming
  (`LiveLocationProvider`, `SimulatedLocationProvider`) is confined to the main actor,
  so the CoreLocation callback and the async stream no longer race for the continuation.
- `Aura` is the app target: SwiftUI views plus the Mapbox-backed implementations of
  the `AuraCore` protocols.

The Xcode project is generated by XcodeGen and is not checked in. Tests run on the
`AuraCore` package and in CI on every push.

### Features

- Free ride and navigate-to-destination modes, both recording a GPS track and live
  stats (distance, moving time, speed, elevation gain).
- Turn-by-turn navigation with spoken instructions, built on Mapbox Navigation v3.
  The guidance lives behind a `GuidanceSession` protocol, so the turn card is driven
  by a plain event stream that a scripted double can replay in tests.
- Route planning returns up to three labeled options (Most paths, Fastest, Flattest)
  from Mapbox Directions. Real elevation comes from decoding Mapbox Terrain-RGB
  tiles, so "Flattest" is ranked on actual climb rather than a guess. "Most paths"
  goes to the most rideable option: a forced-dismount (walking) segment now counts
  against a route instead of for it. The route preview formats its stats with the
  shared `RideStatsFormatter`, so it honors the distance-units setting like the rest
  of the app.
- Persistence with SwiftData, a History list, and a Settings screen (units, voice,
  map style, offline Pittsburgh map download, weekly distance goal).
- A home dashboard: a weekly goal ring, a last-ride card, and a recents list that
  now survives relaunch.
- Route thumbnails in History and on the dashboard (drawn as a Canvas polyline, not
  a live map per row), and a per-route elevation sparkline in the route preview.
- Type scales with Dynamic Type across every screen: semantic text styles for labels
  and headings, and `@ScaledMetric` for the glanceable HUD and ring numerals, which
  stay inside their bounds at accessibility sizes. The ride HUDs and route preview
  clear the status bar with the safe area rather than a fixed inset.

## Next steps

### Features

- A Live Activity and Dynamic Island for an in-progress ride (elapsed time, distance,
  next turn) so the rider can glance at the Lock Screen.
- HealthKit: write completed rides as cycling workouts.
- Haptics on turn approach and arrival.

### Smaller fixes

- Per-route elevation sparklines are normalized to their own min and max, so a flat
  route and a hilly one can look similar. A shared vertical scale across the visible
  options would make the comparison honest at a glance.

## Testing

The `AuraCore` package has 102 tests covering the pure layer: GPX parsing, stats and
ranking (including that "Most paths" avoids forced-walking routes), unit conversion,
the turn-card and guidance pipelines, the week-to-date aggregation, and the plotting
math. UI work is verified by running the app on the
simulator and checking the actual screens, since a clean build is not enough to catch
a feature that silently does nothing (the Terrain-RGB elevation switch is the cautionary
tale: the first implementation compiled fine and returned a flat value everywhere).
